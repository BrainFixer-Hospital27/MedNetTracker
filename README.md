# MedNet Tracker

Учёт и картографирование сетевой инфраструктуры больницы: от порта на
коммутаторе Cisco в серверной до конкретного принтера в кабинете.

Система отвечает на вопросы, ради которых обычно поднимают три таблицы
и звонят двум людям:

- в какую розетку воткнут этот компьютер и на какой порт коммутатора она заведена;
- что вообще стоит в 214-м кабинете и кто за это отвечает;
- какие порты SW-03 свободны и куда уходят занятые;
- где физически находится устройство с этим MAC-адресом.

## Быстрый старт

Нужен **Node.js 22.5 или новее** — в нём есть встроенный модуль
`node:sqlite`, на котором работает база. Проверить версию: `node -v`.

Ничего компилировать не придётся: все зависимости на чистом
JavaScript, Visual Studio Build Tools и Python не нужны.

```bash
npm install                       # зависимости
cp .env.example .env              # настройки
```

Откройте `.env` и задайте два обязательных значения:

```
ADMIN_PASSWORD=ваш-пароль
SESSION_SECRET=длинная-случайная-строка
```

Ключ подписи сессий удобно сгенерировать так:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Дальше — на выбор:

```bash
npm start          # чистая база, всё заводится вручную
npm run seed       # то же плюс демонстрационные данные для знакомства
```

Приложение поднимется на `http://localhost:3000`. Учётная запись
администратора создаётся при первом запуске из `.env`; дальше пароль
меняется в интерфейсе, а в базе хранится только его bcrypt-хеш.

### Команды

| Команда | Что делает |
|---|---|
| `npm start` | запуск сервера |
| `npm run dev` | запуск с автоперезагрузкой при правках |
| `npm run seed` | демонстрационные данные (`-- --force` — поверх существующих) |
| `npm run reset` | полный сброс базы и загруженных планов |
| `npm run check` | ревизия связей (`-- --fix` — исправить) |
| `npm run backup` | снимок базы на работающем сервере |

## Как это устроено

**Сервер** — Node.js и Express, база SQLite в одном файле
`data/database.sqlite`. Работа с базой идёт через встроенный в Node
модуль `node:sqlite`: он синхронный, не требует пула соединений и, что
важнее, не содержит нативного кода. Вся схема лежит в
`server/schema.sql` и разворачивается при старте, без миграционного
тулчейна.

Зависимостей всего четыре, и все на чистом JavaScript:
`express`, `express-session`, `bcryptjs`, `dotenv`. Установка сводится
к распаковке файлов — компилятор C++ не нужен ни здесь, ни на целевом
сервере.

Между `node:sqlite` и распространённым пакетом `better-sqlite3` есть
расхождения в мелочах: нет методов `pragma()` и `transaction()`,
параметры `undefined` и `true`/`false` вызывают ошибку привязки, у
исключений другой формат. Всё это закрывает тонкая обёртка
`server/sqlite.js` — остальной код о разнице не знает.

**Клиент** — Vue 3, Vue Router и Pinia, подключённые как нативные
ES-модули через `importmap`. Сборщика нет вообще: правите файл в
`public/js` — обновляете страницу. Библиотеки лежат локально в
`public/vendor`, обращений в интернет приложение не делает, поэтому
работает в изолированном контуре.

```
server/
  schema.sql      схема базы
  sqlite.js       обёртка над встроенным node:sqlite
  catalog.js      справочник типов оборудования и правил подключения
  model.js        сборка цепочек, проверки связей
  routes/         маршруты API
public/
  js/stores/      состояние (сессия, справочник, карта)
  js/components/  карта, панель осмотра, формы, поиск
  js/views/       экраны
data/
  database.sqlite база
  svg/            планы этажей
```

### Справочник как единая точка правды

Файл `server/catalog.js` описывает все типы оборудования: к какому слою
карты относится тип, какими средами он подключается вверх, что принимает
снизу, какие поля показывать в карточке. Из этого одного описания растут
переключатели слоёв, содержимое форм, правила перетаскивания и проверки
на сервере. Клиент забирает справочник через `GET /api/meta`.

Добавить новый тип оборудования — значит дописать один объект в этот файл.
Ни трогать формы, ни править фильтры не придётся.

### Связи и цепочки

Восходящая связь устройства («во что воткнуто») хранится двумя
колонками — `uplink_socket_id` и `uplink_device_id` — с ограничением
«заполнена не более одной». Так за целостностью следит сама база через
внешние ключи. Наружу, в API, колонки склеиваются в объект
`uplink: { kind, id, medium }`.

Такая схема покрывает всю цепочку из технического задания единым
механизмом:

```
Принтер USB → Системный блок → Свитч → Розетка → Порт SW-01
```

Разрывы допустимы и не считаются ошибкой: розетка может быть не заведена
на коммутатор, устройство — вообще ни к чему не подключено. Цепочка в
таком случае просто короче, а панель осмотра прямо показывает, где она
обрывается.

Кольца исключены: перед сохранением связь проверяется обходом вверх.

### Что к чему можно подключать

Правила выводятся из справочника автоматически. Каждый тип объявляет,
какими средами он подключается вверх (`uplink`) и какие принимает снизу
(`accepts`); связь возможна, если нашлась общая среда. Из этого следует,
например:

| Хотим подключить | Куда | Итог |
|---|---|---|
| компьютер | в коммутатор или розетку | можно, Ethernet |
| USB-принтер, сканер | в компьютер | можно, USB |
| компьютер | в другой компьютер | нельзя |
| USB-принтер | в коммутатор | нельзя |
| IP-камера | в розетку, коммутатор, PoE-коммутатор, регистратор | можно, только Ethernet |
| IP-камера | по Wi-Fi куда угодно | нельзя, камеры проводные |
| что угодно | в сетевой принтер | нельзя, это конечное устройство |

Правило применяется в четырёх местах сразу: список допустимых целей в
форме, подсветка и курсор при перетаскивании, проверка на сервере перед
записью и проверка при смене типа уже подключённого оборудования.
Последнее важно: тип задаёт правила, поэтому его переназначение способно
задним числом сделать существующую связь невозможной. Такая правка
отклоняется с объяснением, а не рвёт связи молча.

### Видеонаблюдение

Камеры вынесены в отдельный слой карты, поэтому подсистему можно
рассматривать отдельно от рабочих мест — или наоборот, скрыть, чтобы она
не мешала.

Типовая схема учтена целиком: на этаже стоит PoE-коммутатор, обычно в
коридоре или подсобке, от него расходятся камеры. Питание идёт по тому
же кабелю, поэтому розетка нужна только самому коммутатору. Сам он
включается либо в розетку, либо в видеорегистратор.

Подключение камеры **только по кабелю** — в розетку, в обычный или
PoE-коммутатор, в роутер, в регистратор. Wi-Fi для камер закрыт на
уровне справочника, поэтому такую связь не создать ни перетаскиванием,
ни через форму.

Цепочка прослеживается насквозь, как и для остального оборудования:

```
IP-камера → PoE-коммутатор → розетка 101/1 → SW-01 / порт 1
```

Это заметно влияет на отчёт «MAC-адреса на портах»: за одним портом
Cisco может оказаться PoE-коммутатор с шестью камерами, и порт увидит
семь адресов. Без такого расчёта расхождение с выводом
`show mac address-table` выглядело бы как посторонние устройства в сети.

### Ревизия базы

Данные могут попасть в базу и в обход приложения — при переносе из
старой системы или правке файла напрямую. Проверить:

```bash
npm run check           # отчёт о нарушениях
npm run check -- --fix  # разорвать недопустимые связи
```

Оборудование при исправлении сохраняется, пропадает только подключение,
которого физически не может существовать. Та же проверка выполняется при
старте сервера: если нарушения есть, в консоли появится предупреждение.

## Планы этажей

Приложению нужны от файла SVG всего две вещи:

1. атрибут `viewBox` у корневого `<svg>`;
2. замкнутые фигуры с идентификатором помещения.

Идентификатор записывается в одной из двух форм:

| Форма | Пример | Когда |
|---|---|---|
| короткая | `room-214` | достаточно всегда: файл относится к одному этажу |
| полная | `b1-f2-r214` | корпус, этаж, помещение |

Полная форма ничего не меняет в привязке, но по ней видно, какому
этажу принадлежит файл. Если загрузить план второго этажа на третий —
приложение это заметит и предупредит. Точный образец идентификатора для
выбранного этажа показан на экране загрузки.

Всё остальное — стены, двери, размерные линии, отсканированная подложка —
рисуйте как удобно, приложение это просто отображает. Складывать фигуры
помещений в группу `layer-rooms` рекомендуется для порядка в файле, но
приложение этого не требует.

Подробное руководство по обводке в Inkscape, с настройками документа,
привязкой масштаба и типичными ошибками: **[docs/INKSCAPE.md](docs/INKSCAPE.md)**.

Образец с правильной структурой: `data/svg/_TEMPLATE_floor.svg`.

Розетки и оборудование в SVG рисовать **не нужно**: их координаты живут
в базе и расставляются мышью прямо на карте.

### Названия помещений

У кабинета есть номер по плану и необязательное название:
«Ординаторская», «Манипуляционная», «Кабинет заведующего». Задаётся
кнопкой «Изменить помещение» в правой панели.

На карте всегда виден только номер — названия и отделения захламляли бы
план. Всё остальное показывается в подсказке при наведении, в панели
осмотра, в поиске и в выгрузке. Если название не задано, помещение
называется «Кабинет 214».

### Привязка происходит сама

При загрузке файла сервер вытаскивает все `room-*`, отрезает префикс и
ищет на этаже помещение с таким номером. Что совпало — связывается
автоматически. Что не совпало — попадает в короткий список расхождений
на экране «Администрирование», где можно либо выбрать помещение вручную,
либо создать недостающие одной кнопкой.

Коридорам, лестницам и санузлам номеров обычно не присваивают — давайте
им буквенные: `room-kor-1`, `room-lest-2`.

### Грабли Inkscape

Сохраняйте через **«Обычный SVG»** (Plain SVG). В «Оптимизированном
SVG» по умолчанию включён пункт **«Сократить идентификаторы»**, который
превратит `room-214` в `g481` и уничтожит всю привязку. Выигрыш в
размере при этом — десятки килобайт, не тот случай, чтобы рисковать.

Инлайновые заливки, которые Inkscape пишет прямо в атрибут `style`,
приложение снимает само при загрузке файла — иначе они перебили бы
раскраску помещений по отделениям.

### Система координат

Задайте `1 единица SVG = 1 сантиметр`. Тогда координаты оборудования
становятся реальными сантиметрами, а иконки на всех этажах получаются
одного физического размера. Держите у всех этажей корпуса общее начало
координат — тогда планы будут накладываться друг на друга.

### Авторазмещение

Геометрию помещений знает только браузер, которому SVG уже разобран.
Поэтому раскладку вновь добавленного оборудования по кабинетам считает
клиент — по габаритам фигур — и отправляет готовые координаты одним
пакетным запросом. Открыли этаж впервые: розетки выстроились вдоль
верхней стены, оборудование легло сеткой ниже. Дальше двигайте мышью.

## Обновление

При запуске без Docker: остановите сервер, замените файлы, запустите
снова.

```powershell
npm install    # только если менялся package.json
npm start
```

База и загруженные планы этажей лежат в каталоге `data` и при замене
файлов не затрагиваются. Недостающие столбцы приложение добавляет само
при запуске. Страницу в браузере достаточно перезагрузить обычным
способом.

При запуске в Docker код лежит внутри образа, поэтому обновление всегда
означает пересборку — `docker compose restart` нового кода не подхватит.
Подробный порядок с резервной копией и откатом:
[docs/DEPLOY.md](docs/DEPLOY.md#обновление), либо готовый скрипт
`./scripts/update.sh`.

## Работа с картой

| Действие | Как |
|---|---|
| Панорамирование | тянуть фон |
| Масштаб | колесо мыши или кнопки слева внизу |
| Выбрать кабинет | щелчок по нему |
| Название кабинета | «Изменить помещение» в панели справа |
| Карточка устройства | двойной щелчок по иконке |
| Переместить | перетащить иконку |
| Переподключить | бросить иконку на коммутатор, роутер, компьютер или розетку |
| Поиск | `Ctrl+K` или `/` |
| Свернуть панель слоёв | кнопка со стопкой слева вверху |
| Свернуть панель свойств | язычок на правом краю карты |
| Переезд между этажами | режим «Всё здание», затем перетащить |
| Разместить со склада | полоса «Не размещено» слева |

Обе панели сворачиваются — освободившееся место сразу занимает карта,
масштаб при этом сохраняется. Удобно, когда нужно окинуть взглядом весь
этаж целиком. На свёрнутом язычке справа остаётся название выбранного
объекта, так что выбор из виду не пропадает.

При перетаскивании цель подсвечивается: зелёным — подключение допустимо,
красным — нет. Перед изменением связи всплывает окно с подтверждением:
перетаскивание слишком лёгкое действие, чтобы молча переписывать схему.

Слои переключаются флажками слева. Связь рисуется только когда видимы оба
её конца: отключили слой «Коммутация» — исчезли и свитчи, и идущие к ним
линии.

### Два режима карты

**Этаж** — повседневная работа. Один план, ничего лишнего.

**Всё здание** — планы всех этажей всех корпусов на одном холсте,
столбцами по зданиям, верхний этаж сверху. Каждый блок подписан.
Нужен, когда оборудование переезжает между отделениями или корпусами:
иконку можно перетащить с четвёртого этажа больничного корпуса в
лабораторный, и координаты сами пересчитаются в систему нового плана.

Во время перетаскивания рядом с курсором показывается полный адрес
цели — корпус, этаж, кабинет, отделение. Без него в общем виде
непонятно, куда именно опускаешь иконку.

Планы для общего вида подгружаются в момент переключения, а не при
запуске: с вшитой растровой подложкой они весят мегабайты, и тянуть их
все ради обычного рабочего дня незачем.

Связь между этажами — стояк — рисуется приглушённым пунктиром: она
законна (видеорегистратор внизу, PoE-коммутатор наверху), но тянется
через весь холст и не должна спорить с содержимым этажа.

### Не размещённое оборудование

Полоса слева, сворачивается в кнопку. В ней всё, что не привязано ни к
какому помещению: складской резерв, заказанное и ещё не привезённое,
запланированное к покупке. Для последних двух случаев добавлены
состояния «Заказано» и «Планируется» — инвентарный номер и модель можно
вписать заранее, ещё до поставки.

Оттуда оборудование перетаскивается прямо на план. Обратно — сменой
помещения на «вне помещений» в карточке.

### Как читать карту

Стиль линии показывает **среду передачи**, а не состояние связи:

| Линия | Среда |
|---|---|
| сплошная | Ethernet |
| длинный пунктир | USB |
| точки | Wi-Fi |

USB-связь всегда оказывается последним звеном цепочки — не по особому
правилу, а потому что USB-периферия по справочнику относится к конечным
устройствам, дальше подключать к ней нечего.

**Разрывы цепочки** обозначаются иначе — красной точкой в углу иконки:
у устройства она означает «никуда не подключено», у розетки — «линия до
коммутатора Cisco не заведена». Полная расшифровка есть в панели слоёв,
раздел «Обозначения».

Некоторые пары соединимы двумя способами: ноутбук подключается к роутеру
и патч-кордом, и по воздуху. В таком случае при перетаскивании и в
карточке появляется выбор среды; по умолчанию предполагается провод.

## Отчёты

Вкладка «Отчёты» в разделе «Администрирование». Наверху задаётся охват —
корпус, этаж, отделение и период для журнала; он действует сразу на все
выгрузки.

Замысел двухслойный. **Реестры** — плоские таблицы «по строке на объект»:
из них сводными таблицами Excel получается любой разрез, в том числе тот,
который никто не предвидел. **Сводки** — готовые ответы на вопросы,
которые задают регулярно.

| Отчёт | О чём |
|---|---|
| Оборудование | полный перечень с реквизитами и цепочкой подключения |
| Розетки, Порты Cisco, Помещения | реестры соответствующих объектов |
| Журнал изменений | кто и что правил за период |
| По состоянию и отделениям | в работе, резерв, ремонт, списано |
| По типам, корпусам, отделениям, ответственным | четыре типовых разреза |
| Подключённость | сколько в сети, по какой среде, сколько без связи |
| Загрузка коммутаторов | занятые и свободные порты по каждому Cisco |
| MAC-адреса на портах | сколько адресов должен видеть каждый порт |
| Распределение портов | группировка портов по числу устройств |
| Качество данных | что не заполнено и требует внимания |

Три способа получить данные:

- **Книга XLSX** — все отчёты сразу, по листу на каждый, с автофильтром
  и закреплённой шапкой. Для дальнейшей обработки.
- **CSV** по отдельному отчёту — разделитель `;`, открывается в Excel
  без мастера импорта.
- **Печатная сводка** — страница, которая сохраняется в PDF штатной
  командой браузера «Печать». Для доклада.

Файлы XLSX формируются собственным кодом (`server/xlsx.js`): формат
Office Open XML — это ZIP с несколькими XML внутри, а zlib в Node уже
есть. Готовые библиотеки умеют больше, но тянут десятки пакетов;
нам нужны только таблицы.

### MAC-адреса на портах

Самый полезный отчёт из перечисленных, потому что он ищет расхождение
учёта с реальностью, а не пересчитывает то, что и так в базе.

Порт Cisco обслуживает одну розетку, но за ней может стоять
неуправляемый коммутатор, а за ним ещё несколько устройств. Значит,
адресов порт увидит столько, сколько устройств с MAC во всём поддереве
ниже него. Приложение считает это число обходом цепочек вниз.

Выгрузите с коммутатора `show mac address-table` и сравните. Порт должен
показывать шесть адресов, а показывает девять — значит, кто-то воткнул
свой коммутатор или ноутбук и никому не сказал.

Отчёт «Распределение портов» показывает то же самое крупным планом:
порты с пятью и более устройствами почти всегда означают неучтённый
коммутатор в кабинете.

### Динамика по месяцам

База хранит текущее состояние: сколько единиц в ремонте сегодня — видно,
сколько было в марте — уже нет. Журнал изменений этого не восстановит,
он фиксирует правки, а не остатки.

Поэтому раз в месяц снимается срез — при первом запуске сервера в новом
месяце. Накопленные срезы попадают отдельным листом в книгу и в
печатную сводку. Кнопка «Снять срез сейчас» пересчитывает текущий месяц
принудительно.

Задним числом эти данные собрать невозможно, так что накопление
начинается с первого запуска этой версии.

## Безопасность

Система рассчитана на одного администратора в локальной сети.

- Пароль хранится хешем bcrypt, сессии — в той же SQLite, поэтому вход
  переживает перезапуск сервера.
- После восьми неудачных попыток входа адрес блокируется на пять минут;
  каждая неудача до этого добавляет задержку ответа.
- Пароли роутеров и Wi-Fi хранятся в открытом виде: доступ к базе есть
  только у администратора, а шифрование при одном ключе на сервере даёт
  лишь видимость защиты. В интерфейсе они закрыты и показываются по
  нажатию, автоматически скрываясь через восемь секунд.
- Все запросы к API, кроме входа, закрыты проверкой сессии.

Если приложение выставляется наружу через nginx, поставьте в `.env`
`TRUST_PROXY=1`, а при работе по https — ещё и `COOKIE_SECURE=1`.

## Если что-то не запускается

**`Встроенный модуль node:sqlite недоступен`** — версия Node старше
22.5. Обновитесь на nodejs.org, лучше до текущей LTS.

**`npm install` пытается что-то собирать через node-gyp** — значит, в
`package.json` попала нативная зависимость. В этом проекте таких нет;
проверьте, что устанавливаете именно его, и удалите каталог
`node_modules` перед повторной попыткой.

**После обновления файлов в браузере старая версия** — сборщика нет,
поэтому имена файлов при обновлении не меняются, и браузер может
показывать закешированное. Сервер отдаёт статику с `Cache-Control:
no-cache`, то есть перед каждым использованием файл перепроверяется по
ETag — обычной перезагрузки достаточно. Если вы обновлялись с версии,
где этого ещё не было, один раз нажмите `Ctrl+F5` (или `Ctrl+Shift+R`).

**Порт занят** — поменяйте `PORT` в `.env`.

**Приложение открывается только на самом сервере** — убедитесь, что
`HOST=0.0.0.0` в `.env`, и разрешите порт в брандмауэре Windows:

```powershell
New-NetFirewallRule -DisplayName "MedNet Tracker" -Direction Inbound `
  -Protocol TCP -LocalPort 3000 -Action Allow
```

## Резервное копирование

Вся система — это каталог `data`. Достаточно копировать его целиком:

```bash
tar czf mednet-$(date +%F).tar.gz data/
```

База в режиме WAL, поэтому для консистентного снимка на работающем
сервере лучше пользоваться штатной командой SQLite:

```bash
sqlite3 data/database.sqlite ".backup 'backup.sqlite'"
```
